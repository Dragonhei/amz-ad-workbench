# AI 广告分析工作台 · 错误码与鉴权规范

> 版本 `0.1.0` · 生成日期 2026-09-12
> 配套阅读：[`API.md`](./API.md)

## 1. 错误响应格式

所有错误均返回 JSON。分为两类信封：

**① 业务异常（`fastapi.HTTPException`）**

```json
{ "detail": "该文件已上传过（ad_report_2026-08.csv，2026-09-10 14:32），请选择覆盖或追加" }
```

**② 请求体校验失败（Pydantic，状态码固定 `422`）**

```json
{
  "detail": [
    { "loc": ["body", "shop_id"], "msg": "value is not a valid integer", "type": "int_parsing" }
  ]
}
```

> 前端应优先读取 `detail`：字符串即直接展示；数组则取各项 `msg` 拼接展示。

## 2. 状态码总览

| 状态码 | 名称 | 含义 | 典型触发场景 | 前端处理建议 |
|---|---|---|---|---|
| `400` | Bad Request | 参数或业务校验失败 | 文件类型不支持、文件为空、未找到表头、规则代码重复、评论为空、渠道缺少 url、无有效数据行 | 直接展示 `detail`，提示用户修正输入 |
| `401` | Unauthorized | 未认证 / 凭据错误 | `X-Username` 对应用户不存在、登录用户名或密码错误 | 提示重新登录 / 切换用户 |
| `403` | Forbidden | 已认证但无权限 | 账号停用、需管理员权限、无店铺数据权限、修改他人评论 | 展示权限不足提示，隐藏相关入口 |
| `404` | Not Found | 资源不存在 | 规则 / 建议 / 运行记录 / 渠道 / 节点 / 方案 / 数据版本 / 知识库类型不存在 | 提示「记录不存在」，刷新列表 |
| `409` | Conflict | 资源冲突 | 重复上传同一文件、同一报表类型同期已有数据版本 | 弹出「覆盖 / 追加」二次确认 |
| `422` | Unprocessable Entity | 请求体 / 参数未通过 schema 校验 | 缺字段、类型错误、枚举越界（Pydantic 自动） | 高亮对应表单字段并展示 `msg` |
| `500` | Internal Server Error | 服务端未捕获异常 | 代码缺陷 / 数据异常 | 提示稍后重试并上报；应视为缺陷修复 |

> **约定**：`409` 专用于「需用户确认（覆盖 / 追加）」的幂等冲突；`400` 的 `detail` 面向终端用户可读，不暴露堆栈。

## 3. 鉴权与权限规则

鉴权采用请求头 **`X-Username`**（缺省 `admin`），实现见 `app/auth.py`。

| 规则 | 位置 | 状态码 | detail |
|---|---|---|---|
| 用户不存在（且系统无任何用户） | `current_user` | `401` | 未找到用户 |
| 用户已停用 | `current_user` | `403` | 账号已停用 |
| 需要管理员权限 | `require_admin` | `403` | 需要管理员权限 |
| 指定店铺越权 | `assert_shop_access` / `resolve_shop_ids` | `403` | 无店铺 {shop_id} 的数据权限 |
| 登录：用户名或密码错误 | `POST /api/admin/login` | `401` | 用户名或密码错误 |
| 登录：账号已停用 | `POST /api/admin/login` | `403` | 账号已停用 |

**权限层级**

| 层级 | 说明 |
|---|---|
| 公开 | `GET /api/health`、`POST /api/admin/login` |
| 登录用户 | 除上述外其余接口默认需通过 `X-Username` 识别身份 |
| 管理员 | `/api/admin/*`（`login` 除外）：用户 / 店铺 / 用量 / 审计 |

**数据范围**

- `admin`：可访问系统内全部店铺。
- `operator`：仅可访问 `User.allowed_shop_ids` 中授权的店铺；请求越权店铺时整单返回 `403`。

## 4. 按资源的典型错误消息

### 数据接入 `ingest`

| 状态码 | detail |
|---|---|
| `400` | 不支持的文件类型 {ext}，仅支持 CSV / TSV / XLSX |
| `400` | 文件为空 |
| `400` | 文件读取失败：{类型}: {信息} |
| `400` | 未找到有效表头，请检查文件是否为广告报表 |
| `400` | 预览已过期，请重新上传文件 |
| `400` | {各字段映射的校验消息，以；拼接} |
| `400` | 没有可入库的有效数据行，请检查字段映射 |
| `409` | 该文件已上传过（{文件名}，{时间}），请选择覆盖或追加 |
| `409` | {报表类型} 在 {起} ~ {止} 已有数据版本，请选择覆盖或追加 |
| `404` | 版本不存在 |

### 智能分析 `analysis`

| 状态码 | detail |
|---|---|
| `400` | 未找到可用的模型配置，请先在「模型与运行配置」中添加至少一个 |
| `400` | 缺少 group 参数 |
| `400` | 规则代码 {code} 已存在 |
| `404` | 配置不存在 / 规则不存在 / 运行记录不存在 / 建议不存在 / 对比分组不存在或已过期 |

### 协作评论 `comment`

| 状态码 | detail |
|---|---|
| `400` | 评论内容不能为空 |
| `403` | 只能修改自己的评论 |
| `403` | 只能删除自己的评论 |
| `404` | 评论不存在 |

### 告警推送 `notify`

| 状态码 | detail |
|---|---|
| `400` | 不支持的渠道类型：{type} |
| `400` | 非邮件渠道必须提供 url |
| `404` | 渠道不存在 |

### 知识库 `kb` / 新品上市 `launch` / 系统管理 `admin`

| 资源 | 状态码 | detail |
|---|---|---|
| kb | `404` | 未知知识库类型 / 记录不存在 |
| launch | `400` | 请填写 ASIN |
| launch | `404` | 方案不存在 / 节点不存在 |
| admin | `400` | 用户名已存在 / 内置管理员不可删除 |
| admin | `404` | 用户不存在 |

## 5. 接口变更约定

- 新增业务校验一律使用 `HTTPException(status_code, detail)`，`detail` 使用中文、面向用户。
- 请求体字段校验交给 Pydantic 模型，自动产出 `422`，不手写重复校验。
- 需要用户二次确认的冲突（如覆盖入库）统一用 `409`，并在 `detail` 中说明冲突对象与可选动作。
